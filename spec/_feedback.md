# 実装に対するフィードバック

- PRの作り方セクションでは純粋に機能としてのPRの作り方を示してほしい
  - 「担当するバグに修正範囲を絞る」の記述がこのタイミングで入ってくるのがわかりづらいと感じた
    - でも大切なことなので、descriptionの重要性の後に、descriptionの重要性と同じトンマナに書き直して移動させよう
  - ブランチを作る、pushする、ディスクリプションを書く、作成ボタンを押す が示したい流れ。
  - diffの確認は不要
  - で、最後にDescriptionの重要性を説明(現行でできている、素晴らしい)
- PRのマージも扉絵を作ろう
- リポジトリの作り方の1個目、「テンプレートを開く」が変な位置で改行されている
- デモプロジェクトの基礎知識03、内容が支離滅裂
  - こういうふうにするなら、タスクリスト、ガントチャート、バーンダウンチャート、集計、絞り込みで順に画像を変えながらリストを増やすべき
  - 表示画像の追加、必要なら撮影して画像追加が必要そう
- デモプロジェクトの基礎知識05、「変更を確認するコマンド」ではく「ソースコードの問題を見つけるコマンド」にする
- デモプロジェクトの基礎知識08、/tasks/:idとTodoDetailViewが被っている
