# スライド仕様の管理

`spec/` は、各スライドで「何を、なぜ、どのように見せるか」を実装とは別に記録する場所です。

## ファイルの対応

`pages/` と `spec/` は、ファイル名を一対一で対応させます。

```text
pages/03_statement.vue
spec/03_statement.md
```

ページ番号と名前を揃えることで、スライド順と仕様の対応をすぐ確認できる状態を保ちます。

## LLM がスライドを書くとき

LLM は、ページを作成・変更する前に次の資料を読みます。

1. `DESIGN.md`
2. この `spec/README.md`
3. 対象ページの `spec/NN_name.md`
4. 対象ページの `pages/NN_name.vue`

対象ページの文章、レイアウト、表示順は、対応する仕様ファイルを見ながら実装します。仕様に書かれていない内容を推測で追加しません。

ユーザーの依頼でページの意図が変わった場合は、先に仕様を更新するか、実装と同じ変更の中で仕様も更新します。

## ページ仕様の書式

新しい仕様は、次の見出しを基本にします。

```markdown
# NN ページ名

- 実装: `../pages/NN_name.vue`

## 目的

このページを見た聞き手に、何を理解してほしいか。

## 表示する内容

必要な文章、数値、コード、図、画像。

## レイアウト

要素の位置、強調、余白、表示順。

## 振る舞い

`v-click`、操作、アニメーション。なければ「なし」。

## 維持すること

変更時にも崩してはいけない意図。
```

必要に応じて「出典」「前後ページとの関係」「未確定事項」を追加します。項目を埋めるための内容は書き足しません。
