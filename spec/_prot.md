# プロット

1. タイトル
2. ハンズオンのゴール
3. 前提(タイトル)
4. 説明すること(PRに関してとバグの調査方法に関してを説明することを頭出し)
5. PRの作り方(タイトル)
6. PRの作り方(マルチページで1ステップ1ページにして説明)
7. PRの作り方 - Descriptionの大切さ
8. PRのマージ方法
9. バグの調査方法(タイトル)
10. バグの調査方法 - バックエンドのログを見る
11. バグの調査方法 - ブラウザコンソールを確認
12. バグの調査方法 - ブラウザの通信履歴を確認
13. プロジェクトのセットアップ(タイトル)
14. リポジトリの作り方(マルチページステップバイステップ)
15. 開発環境のセットアップ(マルチページステップバイステップ)
16. デモプロジェクトの基礎知識(マルチページステップバイステップ)
17. 全部で何個バグがあるか


## 補足

- リポジトリは、https://github.com/petaxa/spot-diff-app から Use this template を用いて作成
- 開発環境のセットアップは、clone → ディレクトリ移動 → npm iまたはpnpm iまたはvp i(これ、ライブラリドキュメントにありがちなタブクリックで表示切り替わりの表現で実装) → vp run dev:all
- デモプロジェクトの基礎知識は、https://github.com/petaxa/spot-diff-app/blob/main/README.md に書いてあること + ルーティング定義がどのファイルにあるか、どういう順で処理が流れるかを1ページ1メッセージのルールに従ってスライドに起こす
- 全部で何個バグがあるか は 12 個
